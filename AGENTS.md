## 🚀 1. Project Overview

PipelineFace is a local knowledge extraction and SEO strategy management system. It scrapes Facebook profiles (via Playwright), catalogs post media in **MongoDB**, transcribes audio (via **Whisper REST**), analyzes visual content/OCR (via **Ollama Vision / moondream**), synthesizes SEO playbooks (via **Ollama Text / qwen2.5**), and presents a web management dashboard built with **FastAPI**, **Tailwind CSS**, and **Vanilla JS**.

## 🗄️ 3. Database Access & MongoDB Schema

MongoDB is the primary persistence layer (`mongodb://localhost:27017`, Database: `pipelineface`).

### Key Collections:
- **`profile_posts`**: Cataloged posts extracted from Facebook profiles.
  - Fields: `post_id` (unique), `profile_url`, `profile_name`, `post_url`, `post_type` (`video`|`image`|`album`), `status` (`pending`|`downloading`|`downloaded`|`processed`|`error`), `media_items` (array of `{media_id, url, type, downloaded, filename, download_error}`), `post_text_preview`, `scroll_position`, `discovered_at`, `updated_at`, `error_message`.
- **`seo_knowledge`**: Extracted SEO strategies generated by `pipeline.py`.
  - Root aggregate `Strategy` embedding: `basename`, `input_file` (`type`: video|image|album, `filename`, `url` (original Facebook URL — the only media display source in the UI), `media_url` (deprecated, always `null`), `size_bytes`, `duration_seconds`), `content` (`transcription`, `transcription_raw`, `visual_description`, `saved_frames` array of `{filename, url}`), `seo_knowledge` (`titulo_estrategia`, `resumo_executivo`, `passo_a_passo_detalhado`, `ferramentas_e_telas_utilizadas`, `termos_e_exemplos_usados`, `aplicacao_no_negocio`, `conceitos_mencionados`, `nivel_dificuldade`, `tempo_estimado_implementacao`, `pre_requisitos`, `resultado_esperado`, `quality_score`, `quality_grade`, `quality_issues`), `metadata` (`author`, `processed_at`, `pipeline_version`), `user_implementation` (`status`, `completed_steps`, `comments`), `updated_at`.
  - **Media display rule**: the UI never serves files from `data/input/` — downloaded media is only the pipeline's input. Display uses Facebook URLs (`url`) and pipeline output frames (`/api/media/frames/...`).
- **`app_config`**: Dynamic key-value system configuration settings.
  - Fields: `key` (unique), `group` (`pipeline`|`models`|`scraper`|`system`), `value`, `value_type` (`string`|`int`|`float`|`bool`), `label`, `description`, `editable`, `updated_at`.
- **`seo_pillars`**: Taxonomy pillars for SEO classification.
  - Fields: `id` (unique slug), `titulo`, `keywords` (array of strings), `ordem`, `ativo`, `created_at`, `updated_at`.
- **`pipeline_runs`**: Execution runs history for pipeline and scraper.
  - Fields: `run_id` (unique), `source` (`pipeline`|`scraper`), `status` (`in_progress`|`completed`|`completed_with_errors`|`error`), `started_at`, `finished_at`, `total_files`, `success_files`, `error_files`, `error_count`.
- **`execution_events`**: Real-time execution logs and telemetry events.
  - Fields: `id`, `run_id`, `source`, `step`, `status` (`info`|`in_progress`|`completed`|`error`), `filename`, `target_url`, `message`, `metrics`, `error_details`, `created_at`.
- **`target_profiles`**: Scraped Facebook profiles history.
  - Fields: `id`, `target_url`, `profile_name`, `last_scraped_at`, `scrape_count`, `last_max_scrolls`, `last_videos_count`, `last_images_count`.
- **`seo_playbook`**: Consolidated SEO Playbook document generated by Map-Reduce synthesis script (`build_seo_playbook.py`).
  - Fields: `id` (`playbook_principal`), `titulo_playbook`, `ultima_atualizacao`, `total_dicas_incorporadas`, `topicos_priorizados` array.
- **`download_history`**: History of downloaded media files to prevent re-downloads.
  - Fields: `url_hash`, `url`, `filename`, `media_id`, `media_type`, `post_id`, `downloaded_at`.

## 💻 5. CLI & Execution Commands

### Running the Scraper CLI:
```bash
# Step 1: Catalog all posts in MongoDB
python3 scraper/facebook_scraper.py --target "https://www.facebook.com/PROFILE" --list-posts

# Step 1 (Only New Posts): Catalog only posts newer than the latest post in MongoDB
python3 scraper/facebook_scraper.py --target "https://www.facebook.com/PROFILE" --list-posts --only-new

# Step 2: Download media for pending cataloged posts in batches of 10
python3 scraper/facebook_scraper.py --target "https://www.facebook.com/PROFILE" --download-pending --batch-size 10
```

### Running the Pipeline:
```bash
# Process all pending files in data/input/ once
python3 pipeline.py

# Continuous daemon mode (every 30s)
python3 pipeline.py --watch --interval 30
```

## 📜 6. Agent Rules & Coding Conventions

When working on this repository, AI agents MUST follow these guidelines:

1. **Clean Architecture Boundary Strictness**:
   - Domain entities ([`web/domain/entities.py`](file:///home/renato/dev/PipelineFace/web/domain/entities.py)) must NOT depend on PyMongo or FastAPI.
   - Routes ([`web/presentation/routes.py`](file:///home/renato/dev/PipelineFace/web/presentation/routes.py)) must delegate logic to Use Cases in [`web/application/`](file:///home/renato/dev/PipelineFace/web/application/).

2. **MongoDB Updates**:
   - Use atomic operations (`$set`, `$setOnInsert`, `upsert=True`).
   - Maintain timestamps in ISO format (`datetime.now().isoformat()`).

3. **Incremental Scraping (`--only-new`)**:
   - Always respect the `--only-new` flag when cataloging posts to avoid re-scanning or duplicating already processed posts.

4. **SEO Implementation Context-First Rule**:
   - Before planning or executing any SEO task, always query existing implementations (`--implemented` or `/api/seo/priorities?status=completed`) and verify existing published pages in WordPress to avoid duplicate slugs or overlapping focus keywords.

5. **Service Restart Protocol**:
   - When modifying backend routes or use cases, notify the user or restart the web service using `./scripts/stop-web.sh` followed by `./scripts/start-web.sh`.

## 🧠 7. SEO Automation Skill & Helper Scripts (`skills/seo-automation/`)

The repository includes a dedicated autonomous execution skill for Studio Githa SEO strategies located in [`skills/seo-automation/`](file:///home/renato/dev/PipelineFace/skills/seo-automation/):

### Core Workflow:
1. **Context-First Audit**: Research completed strategies via CLI/API and check existing WordPress pages/drafts and Google Search Console indexation to prevent duplicates.
2. **Prioritize Pending**: Fetch top business priorities (`/api/seo/priorities?status=pending` or `manage_seo_knowledge.py --pending`).
3. **Mark In-Progress Immediately**: Set strategy status to `in_progress` (`manage_seo_knowledge.py --in-progress <basename>`) as soon as selected to avoid mixing what is being done with what is pending.
4. **Load Execution Plan**: Request enriched plan (`/api/seo/execution-plan/{basename}`).
5. **Browser Execution via Chrome DevTools MCP / REST API**:
   - Build Dark Luxury pages on WordPress (`https://studiogitha.com/wp-admin`).
   - Ensure Rank Math SEO Score **>= 80/100 (Verde)** with single local keyword mention in hero.
   - Configure LocalBusiness Schema.org and request indexing in Google Search Console.
6. **Atomic Single-Strategy Update**: Mark execution as completed 1-by-1 (`manage_seo_knowledge.py --mark <basename>` or `/api/seo/mark-applied/{basename}`).
