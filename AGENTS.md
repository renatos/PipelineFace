## 🚀 1. Project Overview

PipelineFace is a local knowledge extraction and SEO strategy management system. It scrapes Facebook profiles (via Playwright), catalogs post media in **MongoDB**, transcribes audio (via **Whisper REST**), analyzes visual content/OCR (via **Ollama Vision / moondream**), synthesizes SEO playbooks (via **Ollama Text / qwen2.5**), and presents a web management dashboard built with **FastAPI**, **Tailwind CSS**, and **Vanilla JS**.

## 🏗️ 2. Architecture & Directory Structure

The web application follows strict **Clean Architecture (Domain-Driven Design)**:

```
PipelineFace/
├── web/                           # FastAPI Application (Clean Architecture)
│   ├── domain/                    # Pure Domain Entities (Pydantic) & Abstract Repository Interfaces
│   │   ├── entities.py            # ProfilePost, Strategy, SEOPillar, AppConfig, ExecutionEvent
│   │   └── repositories.py        # Abstract Repository interfaces (ABC)
│   ├── application/               # Business Use Cases
│   │   ├── post_use_cases.py      # List, catalog, download pending posts
│   │   ├── strategy_use_cases.py  # SEO Knowledge & Strategy management
│   │   └── config_use_cases.py    # App configuration management
│   ├── infrastructure/            # Concrete Implementations (PyMongo, Process Runner)
│   │   ├── mongo_repository.py    # PyMongo implementations of abstract repositories
│   │   ├── process_runner.py      # Subprocess execution & output capturing
│   │   └── media_service.py       # Media file system operations
│   ├── presentation/              # FastAPI Router & Endpoint Definitions
│   │   └── routes.py              # REST API endpoints & Webhook handlers
│   ├── templates/                 # Jinja2 / HTML5 Templates (Tailwind CSS Glassmorphism)
│   └── main.py                    # Application Entrypoint & Dependency Injection Assembly
├── scraper/                       # Playwright-based Scraper Engine
│   └── facebook_scraper.py        # Facebook profile scraper (CLI & Python API)
├── scripts/                       # Service Control & Utility Scripts
├── pipeline.py                    # Main 100% Python AI processing & extraction pipeline
├── docker-compose.yml             # Container orchestration (MongoDB, Whisper, Web App)
└── Containerfile                  # Container build instructions
```

## 🗄️ 3. Database Access & MongoDB Schema

MongoDB is the primary persistence layer (`mongodb://localhost:27017`, Database: `pipelineface`).

### Key Collections:
- **`profile_posts`**: Cataloged posts extracted from Facebook profiles.
  - Fields: `post_id` (unique), `profile_url`, `profile_name`, `post_url`, `post_type` (`video`|`image`|`album`), `status` (`pending`|`downloading`|`downloaded`|`processed`|`error`), `media_items` (array of `{media_id, url, type, downloaded, filename}`), `discovered_at`, `updated_at`.
- **`seo_knowledge`**: Extracted SEO strategies generated by `pipeline.py`.
- **`pipeline_runs`**: Real-time execution logs and telemetry events.
- **`download_history`**: History of downloaded media files to prevent re-downloads.
- **`seo_pillars`**: Taxonomy pillars for SEO classification.
- **`app_config`**: Dynamic system configuration settings (max scrolls, Whisper model, etc.).

## 🛠️ 4. Scripts Directory Guide (`/scripts`)

Use the shell scripts in the `scripts/` directory to manage services and tasks:

| Script | Command | Purpose |
| :--- | :--- | :--- |
| **Start Web Stack** | `./scripts/start-web.sh` | Launches Podman/Docker compose stack (MongoDB, Whisper, Web App). |
| **Stop Web Stack** | `./scripts/stop-web.sh` | Cleanly terminates all containers and web services. |
| **Check Status** | `./scripts/check-status.sh` | Displays container status, CPU/RAM usage, Ollama API health, and file counts. |
| **Clean Database** | `python3 scripts/clean-db.py` | Resets or cleans MongoDB collections. |
| **Scrape Wrapper** | `./scripts/scrape.sh` | Shell wrapper for launching `facebook_scraper.py`. |
| **Build SEO Playbook**| `python3 scripts/build_seo_playbook.py` | Consolidates cataloged knowledge into an SEO Playbook. |

## 💻 5. CLI & Execution Commands

### Running the Scraper CLI:
```bash
# Step 1: Catalog all posts in MongoDB
python3 scraper/facebook_scraper.py --target "https://www.facebook.com/PROFILE" --list-posts

# Step 1 (Only New Posts): Catalog only posts newer than the latest post in MongoDB
python3 scraper/facebook_scraper.py --target "https://www.facebook.com/PROFILE" --list-posts --only-new

# Step 2: Download media for pending cataloged posts in batches of 10
python3 scraper/facebook_scraper.py --target "https://www.facebook.com/PROFILE" --download-pending --batch-size 10
```

### Running the Pipeline:
```bash
python3 pipeline.py --process-all
```

## 📜 6. Agent Rules & Coding Conventions

When working on this repository, AI agents MUST follow these guidelines:

1. **Clean Architecture Boundary Strictness**:
   - Domain entities ([`web/domain/entities.py`](file:///home/renato/dev/PipelineFace/web/domain/entities.py)) must NOT depend on PyMongo or FastAPI.
   - Routes ([`web/presentation/routes.py`](file:///home/renato/dev/PipelineFace/web/presentation/routes.py)) must delegate logic to Use Cases in [`web/application/`](file:///home/renato/dev/PipelineFace/web/application/).

2. **MongoDB Updates**:
   - Use atomic operations (`$set`, `$setOnInsert`, `upsert=True`).
   - Maintain timestamps in ISO format (`datetime.now().isoformat()`).

3. **Incremental Scraping (`--only-new`)**:
   - Always respect the `--only-new` flag when cataloging posts to avoid re-scanning or duplicating already processed posts.

4. **Service Restart Protocol**:
   - When modifying backend routes or use cases, notify the user or restart the web service using `./scripts/stop-web.sh` followed by `./scripts/start-web.sh`.
